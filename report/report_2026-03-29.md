## 3. Failure Analysis

### Failures #1 / #2 / #3 — `OnlyHardhatNetworkError` (AccessManaged)

`@nomicfoundation/hardhat-network-helpers` methods `increaseTo` and `impersonateAccount` are restricted to Hardhat Network only and throw `OnlyHardhatNetworkError` when connected to VeChain Thor.

**Root cause:** These three tests require either:
- Time advancement (`networkHelperTime.increaseTo`) — needs VeChain-specific equivalent
- Account impersonation (`impersonate`) — VeChain Thor does not support EIP-3085-style account unlocking via `hardhat_impersonateAccount`

**Recommendation:** Replace `networkHelperTime.increaseTo` with VeChain's `time.forward.timestamp` helper and implement a VeChain-compatible impersonation mechanism (e.g., using a pre-funded test account with known private key instead of impersonation).

### Failure #4 — `reverts if closing the manager` (AccessManager, pre-existing)

This failure pre-dates this migration session. The test expects `setTargetClosed(manager, true)` to revert, but VeChain's AccessManager does not enforce this restriction. This is a known behavior divergence between the upstream OpenZeppelin implementation and the VeChain fork.

### Failure #5 — `out of bound delay` (AuthorityUtils)

`web3.utils.toBN(MAX_UINT64)` is `18446744073709551615`, which exceeds the ABI-encodable `uint32` range for the `_setDelay()` function parameter.

**Recommendation:** The `_setDelay` mock contract should accept `uint64` to allow testing the truncation behavior, or the test should call the internal storage directly. Check `AuthorityDelayMock` contract parameter types.
